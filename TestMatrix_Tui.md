## Issues Found and Fix

### Initial file name in shared fake dialogs

Both Open and Save ignored the supplied initial file name. The shared service now passes it to each dialog factory, and the ordinary/TUI picker resources initialize their editor from that value. A regression for an absolute Open path and a relative Save name failed before the fix, then all 28 file-dialog tests passed. The rebuilt native Kitty app displayed and accepted the initial Open/Save names, applied the default extension, and preserved results on cancel at both terminal sizes. Other file cases already passed: filters, single/multiple selection, navigation, empty/missing paths, create/overwrite confirmation, default extension, cancel preservation, English/Chinese and compact layout.

### Hosted click after modal replacement

Kitty could omit pointer motion at unchanged coordinates. A new hosted modal then inherited stale hover state and ignored an OK click. LLDB ruled out an early test-fixture lifetime mistake; the corrected regression failed its hit-test assertion before the fix. Hosted MouseDown refreshes the window/control hover only when the pointer or hovered window changed. The first unconditional version added duplicate move notifications; the full-suite event-count assertion caught this, and the narrowed version passes all 54 TUI/list-control cases. Both the original and final narrowed builds passed 25 consecutive native no-motion modal pairs. The final build also passed ordinary mouse input, child movement/close, and normal queued Stop with restored terminal modes and a usable shell.

### Linux resource build dependencies

The compiler configuration omitted TUI fake-dialog sources, and metadata generation omitted the TuiSkin source set. Added those owning-source dependencies to the vmake configurations and regenerated their build files. Both architecture resource outputs now generate and merge successfully; Linux metadata is generated and tested in its supported x64 configuration.
